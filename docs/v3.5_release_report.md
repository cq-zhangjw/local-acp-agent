## 一、本次迭代目标

推理模型（Bonsai-2-27B / Ornith-1.5 / Qwen3 / DeepSeek-R1 等）在正式回复前会先生成一段思考（reasoning）。此前前端在思考期间收不到任何 `agent_message_chunk`，画面停住像卡死。本次迭代实现：

1. **思考内容实时流式展示**：淡蓝 ThoughtCard 实时滚动，完成后自动折叠为「已思考 · Xs · Y chars」一行摘要；
2. **上下文用量计数修正**：`/api/context/current` 的用量百分比纳入 system prompt + tool schemas 的 overhead；
3. **UI 细节打磨**：子智能体面板、Agent 下拉框、历史会话思考卡片行为修复。

## 二、核心实现：两层 Monkey-Patch（`acp_agent.py`）

### 第一层：langchain-openai delta 解析

`langchain-openai` 的 `_convert_delta_to_message_chunk` **不解析** `reasoning_content` 字段（DeepSeek / ninfer / llama.cpp 的约定），即使 HTTP 响应里有该字段也会被直接丢弃。

在 `acp_agent.py` 模块级包一层，把 delta 里的 `reasoning_content` 塞进 `additional_kwargs`：

```python
import langchain_openai.chat_models.base as _loc
_orig = _loc._convert_delta_to_message_chunk

def _convert_delta_with_reasoning(_dict, default_class):
    msg = _orig(_dict, default_class)
    rc = _dict.get("reasoning_content")
    if rc and hasattr(msg, "additional_kwargs"):
        msg.additional_kwargs["reasoning_content"] = rc
    return msg

_loc._convert_delta_to_message_chunk = _convert_delta_with_reasoning
```

### 第二层：`_content_updates` 转发

`deepagents_acp/server.py` 的 `_content_updates()` 原本只认 `content_blocks` 里的 `type=reasoning` 块。patch 它，额外检查 `additional_kwargs` 里的 `reasoning_content`，包成 `AgentThoughtChunk` 发出：

```python
def _content_updates_with_reasoning(message, message_id=None):
    updates = _orig_content_updates(message, message_id)
    ak = getattr(message, "additional_kwargs", {}) or {}
    rc = ""
    for k, v in ak.items():
        if isinstance(v, str) and v and any(tag in k.lower() for tag in ("reason", "think")):
            rc = v
            break
    if rc:
        updates.append(_da_server.AgentThoughtChunk(
            session_update="agent_thought_chunk",
            content=_da_server.text_block(rc),
            message_id=message_id,
        ))
    return updates
```

两层 patch 都在 `acp_agent.py` 模块级执行，import 时即生效，**不改 site-packages**。

| DeepSeek API | `delta.reasoning_content` | ✅ |

## 三、前端：`ThoughtCard.vue` + `ChatPage.vue`

### ThoughtCard.vue（新组件）

- **思考中**：淡蓝卡片实时流式 + 计时器（200ms 刷新）；
- **完成**：自动折叠成一行「已思考 · Xs · Y chars」，点击可展开；
- **计时器在 done 时冻结**（历史消息 `done=true` 不启动计时，避免刷新后每张历史卡片从 0 秒重新累加）；
- **流式时自动滚动到底部**（done 后不再强制滚动，方便用户回看）；
- **60ms 节流**：reasoning 文本批量刷新，避免每个 token 重渲染 1400+ 字卡片；
- 思考文本 < 200 字符时不显示卡片（调用方判断）。

### ChatPage.vue

- 新增 thought segment 渲染 + 60ms 节流；
- 工具调用后**启动新的思考卡片**（此前一张卡片会一直累加，无法区分多轮思考）；
- 子智能体面板：展示**所有** agent 并带启用开关；子智能体列表使用 linked subagents；
- Agent 下拉框：图标与文字间距 14px → 3px；task 模式下用 `isChatMode` 隐藏 Chat 选项。

## 四、上下文用量修正（`api/context.py`）

`GET /api/context/current` 的用量百分比此前只按消息 token 计算，未计入 system prompt + tool schemas。修正后：

```
usage% = (messages_tokens + system_prompt_tokens + tool_schemas_tokens) / CONTENT_SIZE
```

前端「上下文 X%」显示与实际 prompt 一致，context debug 视图（`maxChars=0` 全量）可核对。

## 八、已知限制与后续方向

1. **每 WebSocket 连接一个独立 agent 子进程**：适合单用户/演示场景，多会话并发需引入会话池（见 `docs/multi-session-parallel-plan.md`）；
2. **reasoning 文本 60ms 节流**：极端高 token 速率下仍可能有轻微滞后，可考虑 `requestAnimationFrame` 方案；
3. **思考卡片折叠后内容保留在内存**：超长思考（>10k 字符）折叠展开时滚动体验可优化；
4. 后续可考虑：思考内容持久化到 history（当前历史只存最终文本）、reasoning 的 token 成本统计、`TTS` 与思考卡片联动（语音模式下跳过思考展示）。
